Claude Code 遇到陌生报错时，可以自行搜索最新文档，再根据查到的内容修改代码。这个过程依赖搜索、抓取和模型自身的工具调用决策，并非简单地在后台打开一个搜索网页。

## 一、搜索与抓取

Anthropic API 提供两个服务端工具：

* WebSearch 用于查找线索。模型生成查询词后，工具返回网页标题、链接和时间等搜索结果。
* WebFetch 用于读取具体页面。它抓取指定 URL，并把网页内容转换成便于模型处理的文本。

模型先用 WebSearch 缩小范围，再按需要调用 WebFetch。是否继续搜索、打开哪个页面，由模型结合当前任务决定。

## 二、动态代码过滤

网页里往往混有广告、导航栏和其他无关内容，全部塞进上下文既浪费 Token，也会干扰判断。Anthropic 在 2026 年 2 月发布的 Claude 4.6 系列搜索工具中加入动态代码过滤，工具版本号为 `web_search_20260209`。

模型可以在沙盒中编写并运行 Python 代码，解析搜索结果或网页内容，只保留当前问题需要的部分。例如，面对一份很长的 API 文档，它可以提取参数表和相关代码片段，再把结果送回上下文。

这项能力目前用于 Opus 4.6 和 Sonnet 4.6。轻量模型和旧版本使用基础搜索流程。

## 三、搜索来源

Claude 的网页和文本检索使用 Brave Search，图像搜索场景可能调用 Bing。它向模型返回便于继续处理的搜索结果，呈现方式与面向用户的传统搜索页面不同。

这种差异会影响使用体验。人使用搜索引擎时会自行浏览结果页、判断来源；Claude 则要把检索结果继续交给模型筛选，有时还会抓取原文并执行过滤代码。

## 四、不同调用渠道的差异

Claude 模型没有公开权重，调用入口主要有以下几类。

### 官方 API 和云平台

企业可以通过 Anthropic API、Amazon Bedrock 或 Google Cloud Vertex AI 调用 Claude。各平台支持的工具和网络策略并不完全相同，接入前应检查 WebSearch、动态过滤和出站访问是否可用。

### 聚合网关和反向代理

第三方中转服务通常在上游账号和调用方之间增加一层代理。WebSearch 能否工作，取决于网关是否完整透传 `tools` 字段、Beta Headers 和工具返回结构。协议字段被裁剪或改写后，普通对话可能仍能使用，搜索工具却会报错。

### 网页接口逆向渠道

还有一些服务通过逆向网页或 App 接口提供兼容 API。这类接口与标准 API 的工具协议差异较大，连接和上下文也容易失效，通常无法稳定支持动态过滤和代码沙盒。

## 结语

如果应用依赖 Claude 的在线搜索，选模型只是第一步。还要确认调用渠道能否透传工具协议，以及对应模型是否支持所需的搜索版本。很多所谓的模型“断网”，问题其实出在中间网关。
